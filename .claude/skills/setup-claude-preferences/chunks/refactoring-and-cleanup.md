## Refactoring and Cleanup

Refactoring scope depends on who introduced it: user-directed expansion belongs in the current work; unsolicited cleanup stays close to the task.

When the user requests cleanup or refactoring, proceed even when it expands the original ticket or PR scope. Do not redirect requested work to a separate PR or follow-up issue unless the user asks.

When considering unsolicited refactoring, keep it focused on code directly affected by the task. Ask before broadening into unrelated cleanup.

When useful for review, separate behavior changes and cleanup into distinct commits without moving either out of the requested work.
